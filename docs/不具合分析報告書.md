# 🐞 Agent 一覧と設定・退避データの不整合

## 🧾 概要

- 対象は Sub Agents Explorer、Agents タブ、Base / Profile / Project の Agent 宣言と無効化時の退避データである。
- **Mid**: 実ファイルがない Agent が Agents タブに残る。Explorer と Manager の列挙基準が異なること、および退避データが単独で行を生成することを確認した。
- **High**: 従来の削除処理はファイル名から role を推測して Base だけを更新するため、別名 role や Profile / Project の参照・退避が残る。共通ファイルの名前変更も参照先の不一致につながる。
- ユーザー指定により、両画面を実ファイル基準へ統一し、不要な退避も整理する仕様に変更した。
- ユーザーの実設定は変更していない。一時ディレクトリで修正前の再現と修正後の確認を行った。

## 🧭 1. 発生メカニズム

| 対象 | 修正前の基準 | 修正後の基準 |
| --- | --- | --- |
| Sub Agents Explorer | 認識済みフォルダの TOML。Base の role 名とファイル名で状態判定 | Agents タブと共通の実ファイル一覧。宣言元設定と role、参照先で状態判定 |
| Agents タブ | 設定宣言と退避宣言。実ファイルがなくても表示 | 実在する Agent TOML に対応する宣言と、未登録の実ファイル |
| config.toml | 削除は Base のファイル名と同名の role だけ | 削除・名前変更は全設定元の参照先パスを照合 |
| agents-disabled.json | 同期でファイルが消えた後も復元用退避を保持 | 実ファイルが残る無効宣言だけ保持し、欠落・削除済み Profile の退避と空ファイルを整理 |

Agent TOML が0件の一時データで、Base に欠落先への宣言 `missing`、退避に `deleted` を用意した。修正前 HEAD の `listAgentManagerRecords()` は2件を返した。修正後の `refreshAgentManagerRecords()` は0件を返し、不要な退避ファイルも消えることを確認した。

実ファイルが残る無効化中の Agent は、引き続き OFF として表示し、退避した宣言から再有効化できる。

## 🧬 2. 混入原因

- 確認済み: `504121a` は Manager を宣言ベースへ変更したが、Explorer はファイル列挙のままであった。旧要件にも「未登録ファイルは表示しない」「参照先がなくても表示する」が含まれていたため、両画面の差は当時の実装・仕様に組み込まれていた。
- 確認済み: 削除と同期はファイル名を Agent ID として扱う処理が残り、role 名がファイル名から独立する仕様や Profile ごとの退避先に追従していなかった。
- 確認済み: 名前変更の回帰確認で、description が未設定の宣言へ description を挿入すると、古い行位置を使って config_file を更新し損ねる既存処理も検出した。
- 未確認: 当時の設計判断・レビュー経緯、および今回の実環境で表示された各項目の元データは取得していない。
- 追加確認: 実ファイル基準への共通化で、新規登録用の `description` が空文字に固定され、Agent TOML の説明を引き継がない回帰を生じさせた。新規一覧・登録時にファイルの説明を読み取り、空の退避説明も再有効化時に補完するよう修正した。空でない宣言の説明と Agent TOML 本体は維持する。

## 🛠️ 4. 対策方針

| 条件 | 両画面の表示 | 設定・退避の扱い |
| --- | --- | --- |
| 実ファイルあり、有効宣言あり | ON | 宣言元設定を維持 |
| 実ファイルあり、無効化時の退避あり | OFF | 復元用退避を維持 |
| 認識済みルートに未登録の実ファイルあり | OFF | 有効化時に実際のパスを登録 |
| config_file なし、または参照先欠落 | 非表示 | 既存の有効宣言は表示時に自動削除しない |
| 実ファイル欠落の退避だけあり | 非表示 | 更新・同期後に整理 |
| 宣言元 Profile 自体が削除済み | その退避からは表示しない | 孤立した退避を整理 |

- 有効な宣言が参照する実在ファイルは、認識済みルート外のパスでも両画面に含める。
- 同じファイルを複数の設定が宣言する場合は、宣言元ごとの行と ON/OFF を維持する。Explorer にも宣言情報を渡し、ファイル名から操作先を推測しない。
- 明示的なファイル削除では、全設定元の参照と退避を取り除いた後に実ファイルを削除する。設定保存に失敗した場合は変更済み設定を戻し、ファイルを残す。
- 名前変更時は、有効・無効の状態を維持したまま、共通ファイルを参照する宣言と退避のパスを更新する。
- 同期用の削除履歴は、同期先への削除伝播に必要なため維持する。無効化時の復元用退避とは区別する。
- 子テーブルを含む宣言の抽出には、develop にある `agentDeclarationService.ts` の処理を再利用し、メタデータ更新と名前変更にも構文位置を利用する。
